# אפיון 13 — מחירים בשקלים לפי שער העברות והמחאות (מכירה) + מחשבון המרה

סטטוס: מאושר לפיתוח · 15.11.2026 · בעלים: סוכן התמחור

## 1. מטרה
הספק מחזיר מחירי טיסה בדולר (לפעמים באירו/ליש״ט). הלקוח הישראלי חושב בשקלים, והבעלים רוצה שהמחיר בשקלים יחושב לפי **שער העברות והמחאות – מכירה** של הבנק (השער שלקוח משלם בפועל כשהוא מעביר מט״ח), ולא לפי השער היציג.
- כל מחיר טיסה באתר מוצג קודם בשקלים (`₪1,234`), המחיר המקורי מופיע כטקסט משני קטן.
- הערה קצרה ליד המחירים: „לפי שער העברות והמחאות – מכירה, נכון ל־<תאריך>”.
- מחשבון המרה קטן ונגיש (סכום + מטבע → ₪ באותו שער).
- כשאין שער: מציגים את המטבע המקורי, בלי ממשק שבור.

## 2. סיפורי משתמש
1. כמטייל, אני רואה בתוצאות החיפוש את המחיר לכל הנוסעים בשקלים, כדי לא לחשב בראש.
2. כמטייל, אני רואה גם את המחיר המקורי ואת השער ותאריכו, כדי להבין מאיפה הגיע המספר.
3. כמטייל, כשאני ממיין „הזולה ביותר” או משווה 3 טיסות, ההפרשים מחושבים בשקלים ועקביים עם מה שמוצג.
4. כמטייל, אני יכול לפתוח מחשבון ולהמיר סכום בדולר/אירו/ליש״ט לשקלים באותו שער.
5. כבעלים, אני יכול לקבוע שער ידני (למשל השער של הבנק שלי היום) שגובר על השער האוטומטי, דרך API מוגן (מסך הניהול ייבנה ע״י סוכן אחר).
6. כבעלים, אם מקור השערים נופל, האתר ממשיך לעבוד (שער אחרון שמור, ואם אין — מטבע מקורי).

## 3. מקורות נתונים (מחקר, 15.11.2026)
| מקור | נגישות מכונה | שער העברות–מכירה? | הערות |
|---|---|---|---|
| בנק לאומי — `https://www.bankleumi.co.il/Rates/Api3.5/ForeignExchange/LatestSelectedRates.aspx` | JSON ציבורי, ללא מפתח | **כן** — `hamchaot.mechira` (העברות והמחאות, מכירה) | גם `yatzig` (יציג) ו־`mezuman` (מזומן). תאריך: `topHeaderText.date`. יין לכל 100. נבדק חי: USD 3.2356 מול יציג 3.199 |
| בנק הפועלים — `/he/coin-rates` | בעבר JSON (`SHAAR_CHK_MECHIRA`), היום מחזיר דף Next.js שגיאה לבקשות שרת | לא נגיש כרגע | לא נבחר |
| דיסקונט, מזרחי טפחות | דפי HTML מרונדרים בצד לקוח; API פתוח (Open Banking) רק לנתוני לקוח בהסכמה | לא | לא נבחרו |
| בנק ישראל — `https://boi.org.il/PublicApi/GetExchangeRates` | JSON ציבורי רשמי | לא — שער **יציג** | גיבוי: יציג + מרווח מכירה מוגדר |

**החלטה:** ספק ברירת מחדל = לאומי (שער העברות והמחאות – מכירה אמיתי). גיבוי = בנק ישראל יציג × (1 + `FX_SALE_MARKUP_PCT`/100). מעל שניהם: שער ידני של הבעלים (`fx:override`).

**ברירת המחדל של המרווח: 1.2%.** נמדד ב־13.11.2026 בלאומי: מרווח העברות–מכירה מעל היציג 1.03%–1.16% (USD 1.14%, EUR 1.07%, GBP 1.06%). 1.2% מעגל מעט למעלה כך שההערכה לא תציג מחיר נמוך מהשער שהלקוח ישלם בפועל ברוב הבנקים. אם הבעלים עובד עם בנק אחר — משנים את המשתנה או קובעים שער ידני.

שמות הבנקים אינם מוצגים בממשק (הבעלים טרם בחר בנק); הם מופיעים רק ב־API (`source`) ובתיעוד.

## 4. ארכיטקטורה
- `backend/fx-rates.mjs` — ספקים נפרדים (`leumi`, `boi`), נרמול ל„₪ ליחידה אחת”, מטמון, שער ידני, ו־handler ל־`/api/fx`.
- `dist/fx.mjs` — מודול משותף (דפדפן + Node, ללא תלות ב־DOM בזמן import): המרה, עיגול, עיצוב, הערה, טעינה.
- `dist/flight-view.mjs` — `formatFare` מציג ₪ כשיש שער; `sortFacts` ממיין לפי `priceBasis` (₪ מעוגל).
- `dist/converter.mjs` + `dist/fx.css` — מחשבון המרה (דף `#/converter` ודיאלוג).
- חיבורים קטנים בלבד ב־`app.js`, `deals-strip.mjs`, `pages.mjs`, `server.mjs`, `index.html`.

### מטמון
- טרי: `FX_REFRESH_HOURS` (ברירת מחדל 4 שעות). אחרי זה, בקשה מגישה את הקיים ומפעילה רענון אחד ברקע (stale-while-revalidate; ב־Vercel דרך `waitUntil`).
- זיכרון + kv (`createStore('fx')`, מפתח `latest`, TTL 14 יום) — כך מופעים מקבילים חולקים שער.
- מטמון קר (אין כלום): ממתינים לרענון עד 4 שניות לכל ספק; כישלון → 503.
- שער מעל 7 ימים: מוגש עם `stale:true`; מעל 14 ימים: לא מוגש.
- כישלון רענון לא מוחק שער קיים.
- הדף לעולם לא מחכה לשער: הלקוח טוען `/api/fx` אסינכרונית ומרנדר מחדש כשהשער מגיע.

## 5. חוזה API
### `GET /api/fx`
200:
```json
{ "ok": true, "base": "ILS", "kind": "transfer-sale",
  "rates": { "USD": 3.2356, "EUR": 3.5773, "GBP": 4.2813, "JPY": 0.020233 },
  "asOf": "2026-11-13", "fetchedAt": "2026-11-15T09:00:00.000Z",
  "source": "leumi", "method": "bank-transfer-sale", "markupPct": null,
  "isOverride": false, "overridden": [], "stale": false }
```
- `rates` = ₪ ליחידה אחת של המטבע (יין מנורמל מ־100 ל־1).
- `source`: `leumi` | `boi` | `override` (כשכל המטבעות ידניים); `method`: `bank-transfer-sale` | `representative-plus-markup` | `manual`.
- `isOverride: true` כששער ידני בתוקף; `overridden` = המטבעות שנקבעו ידנית (גוברים על האוטומטיים, השאר נשארים אוטומטיים). `asOf` במצב זה = תאריך קביעת השער הידני.
- `Cache-Control: public, max-age=600, s-maxage=1800, stale-while-revalidate=86400`.
503 כשאין שום שער: `{ "ok": false, "error": "fx_unavailable", "rates": null }`.

### `PUT /api/fx/override` (Bearer `LEADS_ADMIN_TOKEN`)
גוף: `{ "rates": { "USD": 3.25, "EUR": 3.6 }, "note": "שער בנק X", "expiresAt": "2026-11-20T00:00:00Z" }`
- מטבעות מותרים: ISO בן 3 אותיות מהרשימה הנתמכת; ערכים 0.001–100 (₪ ליחידה). `expiresAt` רשות (עתידי, עד 90 יום); בלי — תקף עד שמבטלים. `note` עד 200 תווים.
- `{ "rates": null }` או `DELETE /api/fx/override` — ביטול.
- תשובות: 200 עם מצב ה־FX החדש; 400 `fx_override_invalid` + `fields`; 401 בלי/עם טוקן שגוי; 404 כשאין `LEADS_ADMIN_TOKEN` (ה־API לא קיים); 429 הגבלת קצב.
- נשמר ב־kv במפתח `override` של namespace `fx` (ב־Upstash: `gerbi:fx:override`).

## 6. תצוגה (UX)
- **פורמט:** `₪1,234` — שקלים שלמים (עיגול לשקל הקרוב), מפריד אלפים עברי, הסמל לפני המספר, בתוך `dir="ltr"`.
- **מחיר מקורי:** טקסט קטן מתחת למחיר: „במקור ‎$1,234.56” (עם `title` המסביר שזה מחיר הספק). לא מוצג כשהמחיר במקור בשקלים.
- **הערת שער:** „לפי שער העברות והמחאות – מכירה, נכון ל־13.11.2026”; בגיבוי בנק ישראל: „לפי הערכת שער העברות והמחאות – מכירה (יציג + 1.2%), נכון ל־…”; שער ישן: מתווסף „· ייתכן שהשער התעדכן”.
- **איפה:** כרטיסי תוצאות (מחיר + מקורי), שורת הסטטוס של התוצאות (הערת שער + כפתור „מחשבון המרה”), טבלת השוואה (מחיר, הפרש בשקלים, הערה), חלון בדיקת מחיר, חותמת „נבדק”, פס הדילים (מחיר לנוסע + מקורי + הערה), טיסות שמורות (בשער של היום, מקורי משני), הודעת וואטסאפ/מייל (₪ + מקורי).
- **סכומים:** המחיר מהספק הוא כבר לכל הנוסעים; ממירים את הסכום הכולל (לא מכפילים מחיר לנוסע מעוגל) — כך הכרטיס, ההשוואה והמיון זהים.
- **מיון/סינון/ניקוד:** „הזולה ביותר” ממיין לפי ₪ מעוגל (גם כשהמטבעות מעורבים, אם לכולם יש שער). הסינון לא תלוי מחיר. הניקוד (scoring) נשאר במטבע המקורי — המרה בשער אחד היא כפל בקבוע ואינה משנה סדר בתוך מטבע אחד.
- **שינוי מחיר בבדיקה:** נקבע לפי המחיר המקורי, כך ששינוי שער לא יוצג כ„המחיר השתנה”.

### מחשבון המרה
- שדה סכום (`inputmode="decimal"`, תווית גלויה), בחירת מטבע (USD/EUR/GBP + שאר המטבעות שיש להם שער), תוצאה ב־`<output aria-live="polite">`, הערת שער.
- זמין: דף `#/converter`, קישור בפוטר, כפתור „מחשבון המרה” בשורת הסטטוס של התוצאות (נפתח בדיאלוג).
- מצבים: טעינה („טוענים שער עדכני…”), שגיאה/אין שער („השער אינו זמין כרגע. נסו שוב מאוחר יותר.” + כפתור ניסיון חוזר), ריק (שדה ריק → „הזינו סכום”), קלט לא חוקי (שלילי/לא מספר → הודעה, בלי חישוב), תוצאה בשתי ספרות אחרי הנקודה.

### מצבי מערכת
| מצב | התנהגות |
|---|---|
| טעינה (השער טרם הגיע) | מחירים במטבע המקורי; כשהשער מגיע — רינדור מחדש אוטומטי |
| יש שער | ₪ ראשי, מקורי משני, הערה |
| שער ישן (>7 ימים) | ₪ + „ייתכן שהשער התעדכן” |
| אין שער / שגיאה | מטבע מקורי בלבד, טקסט „במטבע הספק”, המחשבון מציג מצב שגיאה |
| מטבע בלי שער (נדיר) | אותו מחיר במקורי; מיון „זולה” מושבת אם יש תערובת |

## 7. מקרי קצה
- יין: הספק המקורי מצטט ל־100 → מנורמל.
- `&quot;` בשמות לאומי — לא בשימוש (מיפוי לפי `currencyID`, ובגיבוי לפי שם).
- ערכים לא מספריים/אפס/שליליים מהמקור — נזרקים; פחות מ־USD ו־EUR → המקור נחשב כושל.
- שער ידני שפג תוקפו — מתעלמים ממנו.
- kv לא זמין — זיכרון בלבד; שמירת שער ידני מחזירה 503.
- מחיר ILS מהספק — מוצג כמות שהוא (מעוגל), בלי „במקור”.
- הפרש שלילי/אפס בהשוואה — לא מוצג.

## 8. משתני סביבה
| משתנה | ברירת מחדל | תיאור |
|---|---|---|
| `FX_PROVIDER` | `leumi` | ספק ראשי: `leumi` או `boi` (הגיבוי הוא תמיד `boi`) |
| `FX_SALE_MARKUP_PCT` | `1.2` | מרווח מעל היציג כשמשתמשים בבנק ישראל (0–5) |
| `FX_REFRESH_HOURS` | `4` | כל כמה זמן לרענן (0.25–24) |
| `LEADS_ADMIN_TOKEN` | — | מגן על `PUT/DELETE /api/fx/override` |

## 9. קריטריוני קבלה
1. `GET /api/fx` מחזיר שערים מלאומי (`source: leumi`, `method: bank-transfer-sale`) עם `asOf`.
2. כשלאומי נכשל — גיבוי בנק ישראל עם `markupPct` מהמשתנה (ברירת מחדל 1.2).
3. כששני המקורות נכשלים ויש מטמון — מוגש המטמון; אין מטמון → 503.
4. רענון לכל היותר פעם ב־`FX_REFRESH_HOURS`; בקשות בזמן רענון אינן מפעילות רענון נוסף.
5. `PUT /api/fx/override` עם טוקן נכון קובע שער שגובר; בלי טוקן → 401; בלי משתנה → 404; קלט לא תקין → 400.
6. ביטול שער ידני מחזיר לשער האוטומטי.
7. כרטיס טיסה מציג `₪` ראשי + מחיר מקורי משני.
8. שורת התוצאות מציגה „לפי שער העברות והמחאות – מכירה, נכון ל־<תאריך>”.
9. מיון „הזולה ביותר” עקבי עם המחירים בשקלים, כולל מטבעות מעורבים.
10. טבלת השוואה: המחירים וההפרשים בשקלים, וההפרש = הפרש המחירים המוצגים.
11. פס הדילים מציג ₪ לנוסע + מקורי.
12. טיסות שמורות והודעת המעקב מציגות ₪ + מקורי.
13. מחשבון: נגיש (תוויות, aria-live), זמין מ־`#/converter`, מהפוטר ומהתוצאות; תוצאה = סכום × שער.
14. בלי שער: כל המחירים במטבע המקורי, אין שגיאות קונסול, המחשבון מציג מצב שגיאה.
15. אין „Volero” בממשק; `npm test` + `npm run check` ירוקים; צילומי מסך 1440/375 ב־`verification/13-pricing/`.
16. משתני הסביבה מתועדים ב־`docs/production-readiness-he.md`.
