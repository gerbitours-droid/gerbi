# אפיון 24 – בונים חופשה בקסם (`#/build`)

**בקשת הבעלים:** "מנגנון שבונה הכול – טיסה, מלונות, חקירת יעדים, רכב, הכול כלול – מתוך הסבר פשוט. מסבירים מה רוצים מהטיול ומקבלים מוצר שלם."

**עיקרון על:** כל מחיר שמוצג הוא אחד משלושה, ותמיד מסומן ככזה:
1. **חי** – מהספק, עם שעת בדיקה ("נבדק ב־14:32").
2. **הערכה** – טווח מחושב מתקציבי היעד בקטלוג, מסומן "הערכה בלבד".
3. **לפי הצעה מנציג** – אין מחיר; נציג חוזר עם הצעה.

ה־AI לעולם לא ממציא מחיר, זמינות, מלון או טיסה. הוא רק משכתב טקסטים (פתיח וכותרות ימים) על בסיס הנתונים שכבר בחבילה, ורק כשמוגדר מפתח.

## 1. מחקר יכולות הספק (בוצע 15.11.2026, בזהירות – 25 קריאות חיות בסך הכול)

הספק (מנוע IRIX של dcs plus, ממשק reseller) מפרסם תיעוד OpenAPI ציבורי לכל שירות שהוא מספק:

**מסקנה:** הספק נותן טיסות ומלונות. את ה"חבילה" אנחנו מרכיבים בעצמנו (טיסה חיה + מלון חי). רכב, העברות ואטרקציות – אין אצל הספק.

### 1.1 ממשק המלונות (מה שאנחנו משתמשים בו)
- **אסימון:** אותו OAuth client-credentials, scope `read:hotels-search` (אסימון נפרד מהטיסות; תוקף 24 שעות; נשמר במטמון).
- **חיפוש לפי יעד – אסינכרוני בלבד:** `POST /hotels/v1/search/start`
  ```json
  { "destination": { "city": { "code": "ATH" } }, "checkIn": "2027-01-10", "checkOut": "2027-01-13",
    "occupancy": { "leaderNationality": 376, "rooms": [ { "adults": 2, "childrenAges": [8] } ] },
    "language": "en_GB", "timeout": 10, "sellingChannel": "B2B", "availableOnly": true }
  ```
  - `destination` מקבל גם `city.id`, `region.id`, `location`, `geofence {latitude, longitude, radius}` ו־`accommodation:[ids]`.
  - `leaderNationality` הוא **קוד מדינה מספרי ISO‑3166** – `376` = ישראל (התקבל; `158`/`9` מהדוגמאות נדחו: "Invalid nationality").
  - תשובה: `{ status:"IN_PROGRESS", srk, tokens:{ async, progress, results } }`.
- **התקדמות:** `GET /hotels/v1/search/progress?token=<progress>` → `{status: IN_PROGRESS|COMPLETED, progress, countHotels, countOffers}`. בפועל: 0% → 51% → 71% → 100% בתוך ~12 שניות.
- **תוצאות:** `GET /hotels/v1/search/results/{srk}?token=<results>&perPage=…&sortField=price&sortOrder=ASC&includeHotelDetails=1&hotelClassifications=3,4,5&boardBasis=AI`
  - `{ pages:{current,total,itemsPerPage,totalItems}, hotels:[ { index, name, stars, minPrice:{value,currency}, boardBasis:[{code, price}], nonRefundable:[…], rateTags, details:{ address, geolocation, shortDescription, mainImage:{url}, categories:[{name:"Family property"}…], facilities } } ] }`
  - `minPrice` = המחיר הנמוך לחבילת החדרים המבוקשת **לכל השהות** (לא ללילה). מטבע הספק (בפועל USD) – מומר לש״ח באתר כמו בטיסות (מפרט 13).
  - קודי פנסיון: `RO` לינה בלבד, `SC` עצמאי, `BB` ארוחת בוקר, `HB` חצי פנסיון, `FB` פנסיון מלא, **`AI` הכול כלול**, `RD` לפי תיאור החדר.
  - מיון: `price|stars|name|recommended|specialDeal|pointOfInterest`; עד 100 לעמוד.
  - **מסננים ברשימות נשלחים כמערך בסגנון PHP** (`hotelClassifications[]=3&hotelClassifications[]=4`, `boardBasis[]=AI`); מחרוזת מופרדת בפסיקים נדחית ב־400 ("Expected array, string given").
  - קוד עיר IATA עובד גם כשהיעד בקטלוג מוגדר בשדה תעופה: רומא = `ROM` (נבדק חי: 1,218 מלונות 3–5★, ~20 שניות). מיפוי FCO→ROM וכו׳ ב־`hotelCityOf`, ו־`hotelCity` בקטלוג גובר.
- **שלבים הבאים (לא בשימוש בשלב זה):** הצעות לפי מלון `…/hotels/{hotelIndex}/offers`, אימות מחיר `…/offers/{offerIndex}/availability` (prebook), בדיקת הזמנה כפולה, הזמנה `…/book` (`write:hotels-book`). ההזמנה עצמה נשארת אצל נציג – כמו בטיסות.
- **תמונות:** `details.mainImage.url` מצביע על שרת הספק (נגיש בלי אסימון). כדי שכתובת הספק לא תופיע באתר, התמונות עוברות דרך `/api/build/hotel-image?src=…` (רשימת היתר: נתיב thumb של הספק בלבד, מטמון יום).

### 1.2 מה שאין אצל הספק – חלופות כנות
- **רכב:** המלצה (כן/לא) מהקטלוג (`transport.carRecommended` + הערה), הערת גיל נהג (בד״כ 21+ ותוספת לנהג צעיר מתחת 25 – "בדקו מול חברת ההשכרה"), **מחיר: "לפי הצעה מנציג"**. קישור לשותף חיצוני – **כבוי כברירת מחדל**; מופעל רק אם `CAR_PARTNER_URL` מוגדר (תבנית https עם `{pickup}`, `{from}`, `{to}`), מסומן "אתר חיצוני – לא ג׳רבי טורס", בלי מזהי שותפים מומצאים.
- **אטרקציות:** רשימה ותוכנית יומית מהקטלוג (שמות וזמני שהייה בלבד, בלי מחירים), קישור חיפוש במפות גוגל לכל פריט.
- **העברות / ביטוח:** שורה "לפי הצעה מנציג" בחבילה, שהנציג מקבל כחלק מהליד.

## 3. חוויית "מסבירים → רואים טיול שלם"

1. **קלט:** תיבת טקסט אחת גדולה (עברית/אנגלית) + שבבים אופציונליים: מי (זוג / משפחה / חברים / לבד), מתי (חודש), תקציב (רמה), סגנון (ים, עיר, טבע, סקי, הכול כלול, רכב). השבבים מוסיפים משפט לטקסט – אין שני מקורות אמת.
2. **הבנה:** "הבנו" (שבבים עם מה שזוהה) + "הנחנו" (למשל 2 מבוגרים, 5 לילות, תאריכים בתוך החודש) – כל הנחה ניתנת לשינוי בשורה.
3. **בנייה מדורגת:** שלד מיידי (יעד, תוכנית, מעשי, רכב) → טיסות חיות → מלונות חיים, כל אחד נכנס בנפרד; אזור `aria-live="polite"` מודיע "הטיסות מוכנות", "המלונות מוכנים".
4. **כרטיסים (בסדר):**
   1. **לאן ולמה** – אם לא נבחר יעד: 3 הצעות עם סיבות מהקטלוג (התאמה לסגנון, עונה, משך טיסה, ישירה, תקציב). בחירה בונה מחדש.
   2. **טיסות** – 3 הבחירות הטובות (ממוצע ההמלצה של האתר: עלות כוללת, גיוון), מחיר בש״ח, שעת בדיקה, "פרטים בחיפוש המלא" (קישור לחיפוש הרגיל באותם פרטים).
   3. **מלונות** – עד 3 מלונות (הכי משתלם / שדרוג / הכי זול שמתאים) לפי: דירוג מינימלי, פנסיון (הכול כלול), התאמה למשפחה ("Family property"), אזור מומלץ (התאמת כתובת), מחיר לשהות ולמשך לילה. אם אין תוצאה חיה: אזור מומלץ + "לפי הצעה מנציג".
   4. **רכב** – מומלץ / לא נדרש / ביקשתם; מחיר לפי הצעה; הערת גיל נהג.
   5. **תוכנית יום־יום** – ניתנת לעריכה: הזזת יום למעלה/למטה, הסרת פריט, החזרת פריט מ"עוד רעיונות", קישור מפה לכל פריט.
   6. **מעשי** – ויזה (הערה כללית + "בדקו במקורות הרשמיים"), מטבע, שפה, אזור זמן, כשרות, שבת, עונה מומלצת.
   7. **סה״כ** – רכיבים חיים מסוכמים; הערכות בנפרד; לנוסע ולכולם; מקרא (חי / הערכה / הצעה); מול התקציב ("בתוך התקציב" / "מעל התקציב ב־…") רק כשיש תקציב בש״ח.
5. **פעולות:** "בנו שוב", שמירה לחשבון, שיתוף קישור, הדפסה/הורדה (תצוגת הדפסה נקייה), **"שלחו לנציג להזמנה"**.

## 5. מודל המחיר

| רכיב | מקור | תווית |
|---|---|---|
| טיסה | הבחירה המסומנת מהספק | **חי** + שעת בדיקה; מומר לש״ח בשער האתר |
| מלון | המלון המסומן מהספק (`minPrice` לשהות) | **חי** + שעת בדיקה; "המחיר הסופי מאומת מול הספק לפני הזמנה" |
| מלון (אין תוצאה) | — | **לפי הצעה מנציג** |
| הוצאות במקום | `dailyBudgetIls` של היעד (קטלוג) × ימים × נוסעים (ילד = 0.6 מבוגר) | **הערכה**: טווח `low–mid` (או `mid–high` לתקציב גבוה / יוקרה); "אוכל, אטרקציות ותחבורה מקומית, בלי לינה" |
| רכב, העברות, ביטוח | — | **לפי הצעה מנציג** |

- **סה״כ חי** = טיסה + מלון (רק מה שחי). **הערכה** מוצגת בנפרד כטווח, ו"כולל הערכה" = חי + טווח.
- לנוסע = סכום ÷ מספר נוסעים (ילדים נספרים כנוסעים).
- מחיר מטבע זר מומר רק אם יש שער; אחרת מוצג במטבע הספק בלי סכום משולב.
- **התאמת `dailyBudgetIls`:** הקטלוג מגדיר אותו כתקציב יומי לנוסע **בלי טיסות ובלי לינה**. אם הקטלוג המשותף יגדיר אחרת – משנים קבוע אחד (`LODGING_IN_DAILY`).
- חבילה שמורה/משותפת שומרת את המחירים עם שעתם; אחרי 30 דקות מוצג "מחיר מ־… – רעננו לפני החלטה" + כפתור רענון.

## 6. עריכה
- שינוי שורה ב"הבנו/הנחנו" (מספר לילות, תאריך התחלה, נוסעים, גילי ילדים, רכב, הכול כלול, דירוג) → בנייה מחדש. טיסות/מלונות נשלפים מהמטמון אם לא השתנו הפרמטרים שלהם.
- החלפת מלון: בחירה בין 3 המלונות; "עוד מלונות" מציג עד 8.
- החלפת אזור: בחירת אזור אחר מהקטלוג משנה את דירוג המלונות (בלי קריאה חדשה לספק).
- רכב: הוספה/הסרה (משנה גם את הליד).
- תוכנית: הזזת ימים, הסרת פריטים, החזרתם.
- שינוי מספר ימים = שינוי לילות → בנייה מחדש.

## 7. מחולל התוכנית (דטרמיניסטי)
- ימים = לילות + 1. יום 1: **הגעה** – פריט קצר אחד (≤2 ש׳) ליד המלון. היום האחרון: **חזרה** – בלי פריטים.
- **קצב:** שעות ביום – עם ילדים מתחת 6: 5; עם ילדים: 6; מנוחה/ים: 5; אחרים: 8. פריטים ביום: ילדים 2, אחרים 3.
- **סינון והעדפה:** ילדים → מעדיפים תגיות `family|kids`, מדלגים על `nightlife|adults`; זוג → `romantic|view|food`; ים → יום חוף כל 2–3 ימים; עיר → `culture|museum|food`.
- **קיבוץ:** פריטים עם אותו אזור (`area`) או אותו סוג (`kind`) באותו יום – פחות מעברים.
- **טיול יום:** מ־5 לילות – יום אחד מ־`dayTrips` (עם רכב אם מומלץ).
- **יום מנוחה:** מ־6 לילות עם ילדים/מנוחה/ים.
- **שבת:** אם שומרי שבת – יום שבת הוא "שבת – מנוחה ליד המלון, בלי נסיעות ובלי קניות"; יום שישי מסתיים מוקדם; אזהרה אם טיסה נבחרה ביום שבת.
- **כשרות:** הערה מהקטלוג (`practical.kosher`) + "מומלץ לתאם מראש".
- **מפה:** `https://www.google.com/maps/search/?api=1&query=<שם, יעד>` (קישור חיפוש בלבד).
- **AI (אופציונלי):** משימה `trip_polish` מקבלת את התוכנית ומחזירה פתיח (2 משפטים) וכותרת לכל יום. אימות: אותו מספר ימים, אורך מוגבל, אין מספרים שלא בנתונים, אין קישורים. כשל → הטקסטים הדטרמיניסטיים נשארים.

### 7.1 דירוג מלונות (`backend/hotels.mjs`)
- מבקשים מהספק את 100 הזולים בדירוג (מינימום−1)…5, ובפנסיון המבוקש; אם אין – אותה רשימה בלי סינון פנסיון (ומסומן).
- ציון: מחיר יחסית לזול המתאים (עד ‎+150%) − כוכבים − התאמה לאזור המומלץ (כתובת/שם) − "Family property" למשפחות − פנסיון מבוקש + קנס מרחק ממרכז העיר (חציון מיקומי המלונות; מעבר ל־3 ק״מ).
- 3 תפקידים: הכי משתלם (ציון), שדרוג (יותר כוכבים), הכי זול שמתאים. פחות מ־3 בדירוג המבוקש → יורדים כוכב אחד ומסמנים.
- המטמון שומר את הרשימה לפי מה שנשלח לספק בלבד, כך שהחלפת אזור מדרגת מחדש בלי קריאה חדשה.

## 8. הבנת הבקשה
- `brief-engine.understandRequest` (נוסעים, גילים, תאריכים/חודש/חג, לילות, תקציב, מוצא, יעדים, ישירה, סגנונות, כשר/שבת/נגישות) + שכבת בונה: הכול כלול / פנסיון, רכב (כן/לא), סקי, טבע, חברים, ירח דבש, דירוג כוכבים, יוקרה/חסכוני, "תציעו לי".
- כמה יעדים: `detectLegs` (מסלול עם תאריכים) או 2–3 יעדים בלי תאריכים → חלוקת לילות שווה ומסלול פתוח.
- כשהכיסוי נמוך ויש מפתח – `partnerUnderstand` (קיים) משלים.
- **תאריכים חסרים:** חודש בלבד → יציאה ביום ראשון הקרוב ל־10 בחודש; בלי חודש → החודש המומלץ הקרוב (≥ 21 יום מהיום) מ־`bestMonths`; לילות ברירת מחדל 5 (משפחה 6, סופ״ש 3). הכול מסומן "הנחנו".
- **ילדים בלי גילים:** חיפוש מלון בגיל 8 משוער + שאלה "בני כמה הילדים?".

## 9. ממשק שרת
| נתיב | תפקיד | הגבלה |
|---|---|---|
| `POST /api/build` | טקסט/שבבים/עריכות → בקשה מאומתת + שלד חבילה (בלי ספק) | `build` 20/דקה |
| `POST /api/build/flights` | `{request, stops}` → חיפוש טיסות (אותו מסלול אימות/מטמון כמו החיפוש), 3 בחירות | `buildSupplier` 8/דקה |
| `POST /api/build/hotels` | `{destinationId, checkIn, checkOut, adults, childAges, board, minStars, area}` → מלונות חיים | `buildSupplier` |
| `GET /api/build/hotel-image?src=` | פרוקסי תמונה (רשימת היתר) | מטמון יום |
| `POST /api/build/share` · `GET /api/build/share/<id>` | שמירת תמונת חבילה מנוקה (30 יום) | `build` |
| `POST /api/leads` `type:"package"` | ליד עם החבילה המובנית | הגבלת הלידים הקיימת |
| `GET/POST /api/account/packages` | החבילות השמורות בחשבון (עד 20) | הגבלת החשבון |

- **מטמון:** טיסות – מטמון החיפוש הקיים (3 דק׳, דה־דופ) + מטמון KV של 20 דק׳ לבחירות. מלונות – KV 30 דק׳ לפי (עיר, תאריכים, הרכב, פנסיון) + דה־דופ בזיכרון. כל השדות מאומתים; הדפדפן לא שולח JSON חופשי לספק.
- **AI:** משימה `trip_polish` ב־`ai-tasks` עם `dailyCalls: 300` ומפסק הפעלה מה־admin כמו שאר המשימות.
- **מצב בדיקות:** `GERBI_SUPPLIER_FIXTURES=1` (רק מחוץ ל־Vercel) מחזיר הקלטות מ־`tests/fixtures/build/` – ל־e2e בלי קריאות חיות.

## 10. מסירה להזמנה, שמירה ושיתוף
- **"שלחו לנציג"**: טופס קצר (שם, טלפון, מייל, ערוץ, הסכמה) → ליד `type:"package"` שמכיל גם את שדות "טיול בהתאמה" (יעד, תאריכים, נוסעים, תקציב, סגנונות, הערות) כדי שתקציר ה־AI, הניקוד והייצוא יעבדו כמו היום, וגם `package` מנוקה (רכיבים, בחירות, מחירים עם שעה, תוכנית).
- **אדמין:** תג "חבילה", טבלה קריאה: יעד, תאריכים, נוסעים, טיסה שנבחרה (מחיר + שעה), מלון שנבחר, רכב, צרכים, סה״כ חי/הערכה, תוכנית מקופלת.
- **אזור אישי:** הפנייה מופיעה ב"הפניות שלי" עם הכותרת "חבילה: <יעד>"; "החבילות שלי" ברשימה נפרדת עם קישור פתיחה.
- **שיתוף:** `#/build?p=<id>` – פתיחה ללא קריאה לספק; מחירים עם שעתם.
- **הדפסה:** `window.print()` עם גיליון הדפסה שמסתיר ניווט ופעולות.

## 12. קריטריוני קבלה
1. `#/build` נטען בעברית ובאנגלית, ב־375 וב־1440, בלי שגיאות ובלי גלילה אופקית.
